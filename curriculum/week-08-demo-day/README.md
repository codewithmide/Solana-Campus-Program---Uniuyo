# Week 8 — Demo Day and continuation

**Time:** one rehearsal plus Demo Day  
**Outcome:** a public, reproducible project story and an owned next step.

## Resources

- [Solana Developer Bootcamp 2026 (video)](https://www.youtube.com/watch?v=2pcm7ICRJKU) — revisit the full-stack examples as you prepare your final demo.
- [GitHub: About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) — make your project understandable to someone seeing it for the first time.

## Core task

Prepare a three-minute demo: user/problem (30 sec), live happy path (90 sec), why Solana (30 sec), evidence/lesson/next milestone (30 sec).

The repository README must include setup, account model, pinned versions, tests, devnet links, limitations, security assumptions, team contributions, and roadmap.

## Acceptance criteria

- A fresh tester can follow the README.
- Build and tests pass from a clean checkout.
- No secrets or personal data are committed.
- Demo has a recorded fallback.
- Claims match what the prototype does.
- Every member owns a visible contribution.

## Peer review and continuation

Score 1–5 on problem clarity, complete flow, correctness, reliability, safety, and learning evidence. Open four weekly milestones, name an owner for each, and schedule the next build session before Demo Day ends.
